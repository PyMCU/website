```python
from pymcu.drivers.bmp280 import BMP280
from pymcu.hal.i2c import I2C
```

Driver for the Bosch **BMP280** barometric pressure and temperature sensor over I2C.

:::danger[Raw ADC counts only — this driver does not give you °C or hPa]
`read_temp_raw()` and `read_press_raw()` return the sensor's **uncompensated 16-bit ADC readings**,
exactly as they come out of registers `0xFA`/`0xFB` and `0xF7`/`0xF8`. They are not degrees
Celsius. They are not hectopascals. They are not scaled, offset, or corrected in any way.

Turning them into real units requires the BMP280's compensation formula, which needs the 24 bytes
of per-chip calibration coefficients from registers `0x88`–`0xA1` and a chain of 32-bit and 64-bit
fixed-point multiplies. **PyMCU's stdlib does not implement that**, and this driver does not read
the calibration block at all. If you need physical units, reading the coefficients and applying
the datasheet arithmetic is left to you.

What the raw values *are* good for, unchanged: detecting that a value moved, thresholding, logging
a trend, or shipping the counts to a host that does the maths.
:::

`BMP280` is a **PyMCU stdlib driver**, not part of MicroPython or CircuitPython — neither
ecosystem specifies a BMP280 class in its core API that PyMCU could mirror, so there is nothing to
switch between and this page shows a single API. You import it exactly as written above whichever
API you use for the rest of your program: a `machine.I2C` sketch and a `busio.I2C` sketch both say
`from pymcu.drivers.bmp280 import BMP280`, and it compiles to the same code in both.

:::note[AVR only]
The I2C back end lives in `pymcu.drivers._bmp280.i2c`. `init()` has an `"avr"` case only, so it
compiles to nothing elsewhere; `read_temp_raw()` and `read_press_raw()` have an explicit
`case _: return 0`, so on any other architecture they return **`0`** rather than failing to build.
Treat a constant zero on a non-AVR target as "unsupported", not as a sensor reading.
:::

## `BMP280(i2c, addr)`

| Parameter | Type | Description |
|---|---|---|
| `i2c` | `I2C` | An initialised `pymcu.hal.i2c.I2C` instance |
| `addr` | `uint8` | 7-bit I2C address — `0x76` with `SDO` tied to GND, `0x77` with `SDO` tied to VCC |

The `i2c` object is a zero-cost abstraction with no runtime representation: it fixes the bus at
compile time and the generated code drives the TWI registers directly.

### BMP280 methods

| Method | Return type | Description |
|---|---|---|
| `init()` | — | Write `ctrl_meas` = `0x27` (temperature ×1, pressure ×1, normal mode) and `config` = `0x00` (no standby delay, IIR filter off) |
| `read_temp_raw()` | `uint16` | Raw temperature ADC counts, register `0xFA` as the high byte and `0xFB` as the low byte |
| `read_press_raw()` | `uint16` | Raw pressure ADC counts, register `0xF7` as the high byte and `0xF8` as the low byte |

Three methods, and that is the entire driver.

Both reads assemble the **MSB and LSB registers only and drop the XLSB**, so you get the top 16
bits of the sensor's 20-bit conversion. That is a deliberate simplification — it keeps the values
in a `uint16` and costs you the bottom 4 bits of resolution.

`init()` puts the sensor in **normal mode**, meaning it converts continuously in the background. A
read never triggers a conversion; it just samples whatever the last one produced. Allow about
10 ms after `init()` before the first read, as the example does.

### Wiring

```text
Arduino Uno          BMP280 breakout
-----------          ---------------
PC4 (A4)    <-->     SDA
PC5 (A5)    <-->     SCL
3V3         <-->     VCC     (most breakouts include a regulator and level shifting)
GND         <-->     GND
GND         <-->     SDO     (selects address 0x76)
```

## Example

This is the [`bmp280` example](https://github.com/PyMCU/pymcu-avr/tree/main/examples/bmp280) from
the AVR backend repository, which builds and runs on an Arduino Uno at 16 MHz. It prints each raw
value as two hex bytes, high byte first.

```python
from pymcu.types import uint8, uint16
from pymcu.hal.uart import UART
from pymcu.hal.i2c import I2C
from pymcu.drivers.bmp280 import BMP280
from pymcu.time import delay_ms


def main():
    uart = UART(9600)
    i2c = I2C()
    bmp = BMP280(i2c, 0x76)

    uart.println("BMP280")

    bmp.init()

    uart.println("OK")

    # Wait for the first measurement to complete in normal mode.
    delay_ms(10)

    temp_raw: uint16 = bmp.read_temp_raw()
    press_raw: uint16 = bmp.read_press_raw()

    temp_hi: uint8 = (temp_raw >> 8) & 0xFF
    temp_lo: uint8 = temp_raw & 0xFF

    uart.write('T')
    uart.write(':')
    uart.write_hex(temp_hi)
    uart.write_hex(temp_lo)
    uart.write('\n')

    press_hi: uint8 = (press_raw >> 8) & 0xFF
    press_lo: uint8 = press_raw & 0xFF

    uart.write('P')
    uart.write(':')
    uart.write_hex(press_hi)
    uart.write_hex(press_lo)
    uart.write('\n')

    while True:
        pass
```

Expected UART output at 9600 baud:

```text
BMP280
OK
T:XXXX     <- raw temperature (hex hi+lo)
P:XXXX     <- raw pressure (hex hi+lo)
```

The `XXXX` values are ADC counts. They will drift as the sensor warms and as the weather changes,
which is the useful signal — but there is no factor you can multiply them by to get degrees or
hectopascals without the per-chip calibration block.

### Watching for a change

Because the counts are monotonic in the physical quantity, comparing successive reads works
without any compensation at all:

```python
from pymcu.types import uint16
from pymcu.hal.uart import UART
from pymcu.hal.i2c import I2C
from pymcu.drivers.bmp280 import BMP280
from pymcu.time import delay_ms


def main():
    uart = UART(9600)
    i2c = I2C()
    bmp = BMP280(i2c, 0x76)
    bmp.init()
    delay_ms(10)

    last: uint16 = bmp.read_press_raw()

    while True:
        now: uint16 = bmp.read_press_raw()
        if now > last:
            uart.println("rising")
        elif now < last:
            uart.println("falling")
        last = now
        delay_ms(1000)
```

## Notes

- Address `0x76` is the common default on breakout boards; `0x77` is the alternative. The BMP280
  and the BME280 share both addresses and much of the register map, but the BME280's humidity
  channel is not exposed by this driver.
- The XLSB registers (`0xF9`, `0xFC`) are never read, so the low 4 bits of each conversion are
  discarded.
- The IIR filter is turned off by `init()`. Raw pressure counts are therefore noisy sample to
  sample; average in software if that matters.
- Each read is two separate I2C register reads (MSB then LSB), so the two bytes are not guaranteed
  to come from the same conversion. At the standard 1× oversampling rate the odds of a tear are
  small, but they are not zero.
