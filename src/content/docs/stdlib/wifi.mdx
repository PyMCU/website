PyMCU can bring up the **CYW43439** radio on a Raspberry Pi Pico 2 W, join an open access
point, and publish a numeric reading to an MQTT broker. The whole stack - gSPI bus
bring-up, the SDPCM control plane, ARP, TCP and a minimal MQTT client - is written in
PyMCU Python and compiled into the firmware.

Read the scope notes below before you plan around it. This is a narrow, working slice of
WiFi, not a general networking stack.

## What is supported today

:::caution[Pico 2 W only]
`pymcu.hal.wifi` is a nine-line facade. It re-exports `CYW43` when the target chip is
`rp2350`, and on **every other chip** it raises:

```
CompileError: WiFi (CYW43439) is only supported on the Pico 2 W (rp2350) so far
```

That includes the original **Pico W (RP2040)** - there is no CYW43 path for it. If you see
WiFi mentioned elsewhere alongside the Pico W, this facade is the authority.
:::

:::caution[Open networks only - there is no WPA]
`connect()` rejects a password at compile time:

```
CompileError: WiFi: WPA is not supported yet; connect() can only join open networks -- leave key empty
```

The `key` parameter exists purely so the signature matches MicroPython's
`WLAN.connect()`. The join path is `join_open()`, which sends no PSK material at all, so a
key would have been silently dropped - the compiler refuses it instead.
:::

:::caution[The firmware blob is stubbed]
The bring-up sequence powers the chip, probes the test register, switches the bus to 32-bit
mode, opens the F1 backplane and takes the WLAN core out of reset - but **firmware download
is intentionally a stub**. There is no 43439 blob, which a real radio needs before it will
transmit. The path is validated end to end against the RP2350Sharp CYW43439 model and its
built-in AP and MQTT broker; treat on-silicon RF as not yet delivered.
:::

## Publish a sensor reading over WiFi

All three flavours below compile to the same radio code - they differ only in which API
names you write. They are taken from the `dht-mqtt-mp-rp2350`, `dht-mqtt-cp-rp2350` and
`dht-mqtt-rp2350` examples in the `pymcu-arm` repo.

<Tabs syncKey="api">
<TabItem label="MicroPython">

```python
import network
from umqtt.simple import MQTTClient
from machine import Pin
from dht import DHT11
from pymcu.types import uint32


def main():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    wlan.connect("RP2350Sharp-AP")      # open network - no key

    sensor = DHT11(Pin(2, Pin.IN))
    sensor.measure()
    t: uint32 = sensor.temperature()

    client = MQTTClient(wlan, "pm", "192.168.4.1")
    client.connect()
    client.publish(t)                   # reading -> MQTT topic "dht"
    while True:
        pass
```

</TabItem>
<TabItem label="CircuitPython">

```python
from pymcu.hal.wifi import CYW43
import socketpool
import adafruit_minimqtt.adafruit_minimqtt as MQTT
from pymcu.types import uint32


def main():
    radio = CYW43()
    radio.connect("RP2350Sharp-AP")     # open network - no key
    pool = socketpool.SocketPool(radio)
    client = MQTT.MQTT(broker="192.168.4.1", socket_pool=pool)
    client.connect()
    reading: uint32 = 42
    client.publish("dht", reading)
    while True:
        pass
```

</TabItem>
<TabItem label="Native HAL">

```python
from pymcu.hal.rp2350.cyw43 import CYW43
from pymcu.types import uint8, uint32


def main():
    wifi = CYW43()
    wifi.init()                         # power + gSPI bring-up
    wifi.join_open("RP2350Sharp-AP")
    wifi.settle()                       # drain the post-join async events
    wifi.mqtt_publish(42)
    while True:
        pass
```

</TabItem>

:::note[The CircuitPython radio is constructed locally]
Idiomatic CircuitPython uses a module-level `wifi.radio` singleton, and
`pymcu_circuitpython/wifi.py` does define one. It compiles, but a cross-module singleton's
method still has a runtime self-binding gap, so the example constructs `CYW43()` inside
`main()` instead. Do the same until that gap closes.
:::

## What `mqtt_publish()` actually sends

`mqtt_publish` is not a general MQTT client. It takes **one `uint32`** and runs a fixed,
fully hardcoded QoS-0 exchange:

| Detail | Value |
|---|---|
| Topic | `"dht"` - not configurable |
| Payload | The value as exactly **three ASCII digits**, so 0 to 999 round-trips and larger values wrap |
| Client id | `"pm"` |
| Broker | `192.168.4.1:1883` |
| Guest address | `192.168.4.2`, MAC `02:00:00:00:00:01` |
| Flow | TCP `SYN` to `SYN-ACK` to `ACK` + `CONNECT`, then `PUBLISH` |
| QoS | 0, no retain, no will |

There is no DHCP and no DNS: the addressing above is compiled in. `publish(value)` is an
alias for `mqtt_publish(value)`.

## Native HAL reference - pymcu.hal.rp2350.cyw43

```python
from pymcu.hal.rp2350.cyw43 import CYW43   # or: from pymcu.hal.wifi import CYW43
```

The class talks to the radio over a **bit-banged gSPI** bus on four GPIOs -
`WL_REG_ON=23`, `WL_DATA=24`, `WL_CS=25`, `WL_CLK=29`. Everything is `@inline`, so the
whole driver collapses into your call sites.

| Method | Description |
|---|---|
| `CYW43()` | Configure the four gSPI pins and park them at idle levels (CS high, clock low, power off) |
| `init() -> uint32` | Power the chip, probe the test register, switch the bus to 32-bit, open the F1 backplane, request ALP/HT clock, release the WLAN core from reset. Returns the test-register read-back |
| `join_open(ssid) -> uint32` | Associate with an **open** AP by sending a `WLC_SET_SSID` ioctl on the SDPCM control channel. `ssid` must be a compile-time string. Returns the frame length sent |
| `connect(ssid, key="")` | Convenience: `init()` then `join_open()` then `settle()`. A non-empty `key` is a compile error |
| `settle()` | Drain the async SDPCM events the chip queues after a join, so a later request/response exchange reads its own reply |
| `f2_available() -> uint32` | Length of the next queued inbound packet, `0` when there is none |
| `f2_read(buf, maxlen) -> uint32` | Read the next inbound packet into `buf`; returns the packet's real length, which can exceed `maxlen` |
| `send_arp()` | Broadcast an ARP request for the gateway from the compiled-in guest address |
| `mqtt_publish(value)` | The fixed publish described above |
| `publish(value)` | Alias for `mqtt_publish` |
| `read32(fn, addr) -> uint32` | Raw gSPI register read - bring-up plumbing, not an application API |
| `write32(fn, addr, val)` | Raw gSPI register write - same caveat |

Methods prefixed with `_` are internal and may change without notice.

## The compat surfaces

### MicroPython - `network` and `umqtt.simple`

```python
import network
from umqtt.simple import MQTTClient
```

| Name | Behaviour |
|---|---|
| `network.STA_IF` / `network.AP_IF` | `0` / `1`. Only station mode is implemented |
| `WLAN(interface=0)` | Constructs the underlying `CYW43` |
| `WLAN.active(on=1)` | Calls `init()` when `on` is non-zero. There is no deactivate path |
| `WLAN.connect(ssid, key="")` | Calls `join_open()` then `settle()`. A non-empty key is the same compile error as the HAL |
| `WLAN.isconnected()` | **Always returns `1`.** It reports no link state at all - do not poll it waiting for an association |
| `MQTTClient(wlan, client_id="pm", server="")` | Borrows the already-connected radio from `wlan`. `client_id` and `server` are accepted and ignored |
| `MQTTClient.connect()` | Returns `0`; the real TCP and MQTT handshake happens inside `publish()` |
| `MQTTClient.publish(value)` | **Signature differs from real umqtt**, which takes `(topic, msg)`. Here it takes one number and the topic is the hardcoded `"dht"` |
| `MQTTClient.disconnect()` | No-op |

### CircuitPython - `wifi`, `socketpool` and `adafruit_minimqtt`

| Name | Behaviour |
|---|---|
| `wifi.radio` | A module-level `CYW43` instance. See the note above about constructing it locally instead |
| `socketpool.SocketPool(radio)` | Carries the radio to the MQTT client; it is not a socket factory |
| `MQTT.MQTT(broker="", socket_pool=None)` | `broker` is accepted and ignored - the address is compiled in |
| `MQTT.connect()` | Returns `0` |
| `MQTT.publish(topic, value)` | The `topic` argument is accepted and **ignored**; the value goes to the hardcoded `"dht"` topic |

## Not available yet

- **WPA / WPA2 / WPA3** - open networks only.
- **The Pico W (RP2040)** - no CYW43 path exists for it.
- **Sockets** - there is no general socket API on either compat surface. `socketpool` only
  forwards the radio.
- **Arbitrary MQTT** - one topic, one numeric payload, no subscribe, no QoS 1 or 2, no
  retain, no last will, no TLS.
- **DHCP, DNS, IPv6** - all addressing is compiled in.
- **Access-point mode** - `AP_IF` is defined but nothing implements it.
- **Link state** - `isconnected()` is a constant.
- **Bluetooth** - not exposed to PyMCU programs.
